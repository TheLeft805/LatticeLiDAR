## 原验收口径

- KITTI 11–21，全局排序每 20 帧取 1 帧；每尺度 1,018 帧、122,581,756 个原始点，尺度为 8/16/32/64 mm。
- 统计完整实际码流，包括封装、包头和状态开销；两端预共享模型与重建权重，模型文件体积不计入逐帧 bpp。
- 所有点云均经过实际独立解码，并对 float32 坐标计算失真。不同方法的 BD-BR 在共同质量区间内计算。
- NVIDIA RTX 4090；CPU 输入到 CPU 码流及独立解码到 CPU XYZ，包含必要传输，排除磁盘与初始化/编译/预热。单轮固定顺序执行。

本次采样中的服务时间不等于持续到达下的实时性保证；单轮结果也不证明细小耗时差异可重复。部分序列曾用于内部验证，本结果不称为严格未见测试集结果，也不代表全部 20,351 帧均完成相同验收。

重建模块相对固定格点的 D1/D2 BD-BR 为 −8.80%/−13.90%，相对仿射重建约再改善 1%。这不是 GELU 激活函数单独的收益：内部 96 帧中，同容量、继续拟合条件下 GELU 相对 ReLU 的额外 D1/D2 BD-BR 为 −0.0312%/−0.0297%。

## 本次打包检查（2026-10-18）

检查冻结源码集合、主权重、重建实现与原始资产的 SHA-256 一致性，执行 CPU 容器契约测试，并检查命令入口与四尺度配置绑定。CLI 已改为最终非线性重建输出，不对米制 XYZ 再次做格点坐标转换。

用户要求本次只做本地整理，因此未在服务器重跑 GPU 编解码或计时。CPU 测试与哈希核对不替代新入口的 GPU 端到端复验；历史性能只对应上面标识的原运行。后续修改核心、运行环境或容量配置后，应重新检查实际码流和独立解码结果。

## 复现实验入口

仓库支持单帧和目录编解码。若要复测耗时，应在同一进程内先初始化并预热，再逐帧测量；每帧重新启动 CLI 会重复编译/建图开销，不适合与上表直接比较。构造样本清单可使用 `tools/build_test_manifest.py`，但其完整 split 清单不等同于本次 every-20 采样清单。

此发布不附带 KITTI 数据、质量指标工具、原始验收日志或完整多方法基准脚本，README 的历史表格不能被理解为一键复现整篇对照实验的承诺。
